# Module 讲义模板：问题驱动的科学叙事

> 目标：每个模块回答一个科学问题，而不是陈列一组相关知识。正文负责建立连续理解，KB 负责展开细节，代码与测试负责验证结论。

## 一章只保留一条主线

开始写作前，先完成这张“章节契约”：

| 项目 | 必须写成一句话 |
|---|---|
| 核心问题 | 读者学完这一章后，究竟能回答什么问题？ |
| 锚点对象 | 哪一个具体系统贯穿现象、模型与推导？ |
| 认知冲突 | 旧语言在哪里不够用，或哪个观察结果出乎预期？ |
| 中心等式 | 哪一条公式完成本章最重要的认知转折？ |
| 可测量量 | 实验或数据中真正能够观测、扰动或估计什么？ |
| 问题链 | 中心概念是什么、为什么需要它、等式两边各表示什么、合起来回答了什么？ |
| take-home message | 删除全部推导后，读者必须记住什么？ |
| 成立边界 | 哪个假设一旦失效，结论就不能照搬？ |

如果一章需要两套彼此独立的锚点对象、中心等式或 take-home message，就应拆章，或把其中一条线下沉到 KB。若两条路线回答同一个问题但依据不同，开头必须明确分支，结尾必须说明它们共享什么、又不能互换什么。

## 三层内容结构

### 1. 主叙事层：连续读完也能理解

正文按下面的因果顺序展开：

1. **问题**：用一个具体观察提出科学问题。
2. **冲突**：说明平衡直觉、旧模型或只看平均值为什么不够。
3. **测量**：先解释实验或数据中测什么，再引入符号。
4. **最小模型**：只加入解释该冲突所需的自由度和参数。
5. **中心推导**：保留完成认知转折所必需的步骤。
6. **物理账本**：解释概率、能量或信息从哪里来、到哪里去。
7. **边界**：说明结论的适用条件及最常见的误读。
8. **迁移**：把同一结构映射到另一个问题，但不偷换物理含义。

主叙事中不要插入安装命令、代码路径清单、长篇历史资料或多个旁支推导。

### 2. 严谨性层：让漂亮结论经得起检查

每个中心等式至少核查四件事：

- **假设**：平衡、稳态、Markov、线性响应、局部细致平衡等条件是否明确？
- **量纲**：等式两边是否同量纲？傅里叶变换后是否缺少频率或阻尼因子？
- **极限**：驱动归零、温度归零、时间趋于无穷或系统退化时是否恢复已知结果？
- **观测边界**：测到的是完整系统、一个自由度，还是粗粒化后的投影？

推导过长时，正文保留“为什么这样写—关键变换—结果意味着什么”，完整代数放入 `kb/derivations/`。

### 3. 可执行层：把理解变成可证伪的预测

一个模块只围绕中心结论建立一个最小闭环：

$$
\text{解析预测}
\longleftrightarrow
\text{数值模拟}
\longleftrightarrow
\text{交互可视化}
\longleftrightarrow
\text{自动测试}.
$$

Notebook、pytest、项目入口和 Checklist 统一后置。它们回答“怎样验证”，不负责首次解释概念。

## 推荐正文模板

```markdown
# Mx 标题：让标题暴露核心问题

用一至两段具体观察提出冲突，并立即给出本章的分析对象。标题已经提出问题时，不再添加“问题”“核心问题”或“本章要回答”重复一遍。

## 1. 旧语言在哪里失效？
只召回当前推理真正依赖的旧结论，不复述上一章。

## 2. 怎样测量这个差异？
先给操作定义，再给符号。

## 3. 最小模型
写清自由度、动力学和噪声/约束来源。

## 4. 中心推导
每个公式之前说明它要回答的问题；之后解释来源、量纲和极限。

## 5. 物理意义
用稳定的术语解释中心结论，不为追求文采反复换同义词。

## 6. 成立条件与常见误读
区分数学恒等式、物理解释、数据 proxy 和经验类比。

## 7. 最小可验证闭环
交互组件、解析预测、Notebook、pytest。

## 8. 迁移与开放问题
说明结构可以迁移到哪里，以及哪些部分不能迁移。

## 9. 核心答案：直接写出 take-home message
用一段话直接回答章首问题；到这里主叙事必须闭合。

## References
只列本章真正使用的 SSOT 条目。

## Checklist
放在全文最后。
```

## 段落与语言规则

- **一段一职**：一段只负责定义、推导、证据、解释或边界中的一种任务。
- **结论在前**：段首点明本段要解决的问题，段末留下 take-home message，而不是预告下一节。
- **问题只出现一次**：标题、章首小标题和引文框不要轮流复述同一个问题。
- **公式必须完成认知任务**：公式前说明为什么需要它，公式后说明每一项在说什么、结论在哪些条件下成立。
- **召回不等于重复**：只有当前推理依赖旧结论时才用一句话召回；不要重新讲一遍上一章。
- **术语稳定**：同一个对象固定一个名称。不要把“概率净流”“环流”“通量”无说明地轮换使用。
- **比喻从一而终**：每章最多保留一个语言锚点；定义完成后回到科学术语。
- **少用元话语**：删除“下面我们将”“你会看到”“这绝不是天降”等不推进论证的句子。
- **少用价值形容词**：用“由量纲可检验”“由对数不等式保证”代替“深刻”“硬核”“伟大”。
- **比喻不替代边界**：直观解释之后必须回到操作定义；特定模型中的非负性、单调性或等价关系不得扩写成普遍定理。
- **行内公式用 `$...$`**，需要独立阅读的等式用 `$$...$$`。

## 类比与城市映射的红线

结构相似不代表热力学等价。城市或社会系统中的映射必须标明属于哪一层：

1. **数学同构**：使用相同的方程或网络结构；
2. **统计诊断**：某个量可作为时间不可逆性或敏感性的 proxy；
3. **物理等价**：只有定义了能量、温度、热浴和局部细致平衡后，才能把量解释为热或物理熵产生。

不得把第 1、2 层直接写成第 3 层。尤其不能仅凭 Markov EPR 就宣称得到真实能耗，也不能把“最小熵产生”当作普遍优化原则。

## 交付前自检

- [ ] 标题和开头是否提出同一个核心问题？
- [ ] 删除所有显式过渡后，段落逻辑是否仍然连续？
- [ ] 每个符号是否在读者知道“为什么需要它”之后出现？
- [ ] 每条中心公式是否说明了假设、量纲、极限和观测边界？
- [ ] 主叙事是否能在不打开 KB 和 Notebook 的情况下读懂？
- [ ] 代码、图和测试是否验证同一条中心结论？
- [ ] 城市映射是否明确区分数学结构、统计 proxy 与物理热力学量？
- [ ] Checklist 和参考资料是否已经后置？
